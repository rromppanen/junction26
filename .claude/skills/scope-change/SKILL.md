# Scope a change

Read the request and existing behavior. Identify the decision that needs clarification before choosing an implementation.

1. Name the affected user, caller or operator and the outcome they need.
2. Describe the relevant starting behavior and the requested difference.
3. State observable acceptance criteria, including significant failure cases.
4. Identify compatibility, data handling, accessibility and operational constraints that affect this change.
5. Separate necessary work from optional improvements. Record explicit exclusions only where confusion would expand scope.
6. Resolve uncertainty through available evidence first. Ask for a missing decision when it changes the outcome or authority.

For a bounded correction, keep this in the task response. Use a retained brief when coordination or duration warrants it.

Return the outcome, scope, acceptance evidence and unresolved decisions. Do not invent a numerical target or silently enlarge the request.
